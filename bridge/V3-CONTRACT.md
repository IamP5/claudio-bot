# Bridge v3 contract

This file maps the v3 bridge: each module's interface, the state it writes, and the rules the modules build on. The doc comments in each module carry the full invariants; this page is the index. A change to an interface listed here updates this page in the same commit.

## State: `state.json` version 3

`world.ts` declares every persisted shape. A slice typed `Owned<T>` is a readonly field holding deeply readonly data, so only its writer can change it. The writer calls `world.own()` and mutates in place.

| Slice | Type in `world.ts` | Only writer | Notes |
|---|---|---|---|
| `BotRecord` profile, `dailyCapUsd` | `BotRecord` | `hub.ts` | `update_bot`, `update_self` |
| `BotRecord.messages`, `.unread` | `Message[]` | `hub.ts` (`say` → `post`) | the gate and scheduler call the hub's `say` and `note`; past 1,100 messages the oldest move to `<bot home>/.history/bot.jsonl` (an agent's to `.history/<agentId>.jsonl`), open cards stay |
| `BotRecord.session`, `AgentRecord.session` | `SessionState` (`Pending`, `ActiveTurn`, `Lifecycle`, `Notice`) | `session.ts` | resume id, durable inbox, lifecycle with deadlines, notices. `Pending.kind` is `continuation` for a decision envelope, `envelope` otherwise; `Pending.settles` names the routine run a turn end settles |
| `World.account` | `AccountState` | `session.ts` | account-wide usage-limit park |
| `BotRecord.routines` | `RoutineRecord[]` | `scheduler.ts` | `nextRunAt`, newest 20 runs, `failStreak` |
| `BotRecord.rules` | `StandingRule[]` | `gate.ts` | Always/Never, keyed by `Signature`, allow rules carry `appliesTo` |
| `World.gate` | `GateState` (`OpenCard`, `Grant`, `DailyCount`, `RepoTrust`) | `gate.ts` | card deadlines (question, permission and trust cards), permission match keys, one-shot grants with the attendance of the card that made them, daily tool counts, trust answers per repo |
| `World.devices` | `DeviceRecord[]` | `devices.ts` | token hashes only; `legacy` marks the imported protocol-2 token |
| `World.push` | `PushState` | `push.ts` | `${messageId}|${reason}` keys (reason `card`, `reminder`, `message` or `result`), recorded before sending |
| `AgentRecord.agent`, `.cloudSession`, `.startedBy` | `Agent`, `string \| null`, `Initiator` | `agents.ts` | cloud agents are neither gated nor metered; `startedBy` is the bot turn's initiator at `start_agent` |

`store.ts` owns the file. `loadWorld` fails closed. `checkStateFile(parsed)` is the pure check it runs, and the doctor runs the same one without loading: every bot and agent record (v3) or every v2 record against the fields the bridge reads. A malformed record, an unknown version, unreadable JSON or a failed upgrade throws `StateFileError` without writing anything. A v3 file written before `Pending.kind` or `GateState.repos` is read with a continuation recognised by its `c_` id prefix and no trust answers. A v2 file is upgraded in memory first, then its exact bytes are copied to `state.v2.json.bak`, then v3 is written in place. A v1 file is backed up to `state.v1.json.bak` and treated as a first run. A backup is never overwritten. When the name holds other bytes, the copy goes to the next free `.1`, `.2` suffix, and bytes already backed up are not copied again.

`flushNow(world, home)` and `saver.schedule("now")` write synchronously. They write the whole body to a temp file with a unique name, `fsync` it, check its size, rename it over `state.json` with mode 0600, then `fsync` the directory. The guarantee is against a crash of this process. On macOS `fsync` does not flush the drive cache (that needs `F_FULLFSYNC`), so a power loss can still lose the newest write. `saver.schedule()` debounces by 250 ms. A failed debounced write is logged, stays pending and retries with a doubling delay capped at 30 s. `saver.schedule("now")` and `saver.flush()` throw when the write fails, with the retry still armed. `Persist = (urgency?: "now") => void` is the type every module receives, and a module whose `persist("now")` throws must not perform the effect the write was meant to precede.

README, upgrading: "Once the new bridge has started, do not run an older bridge against the same home. It does not know state version 3, treats the file as a first run and overwrites it. To go back, stop the new bridge and copy `state.v2.json.bak` over `state.json` first; anything changed since the upgrade is lost."

## Rules each module builds on

- **Initiator.** `prompts.initiatorOf(envelope)` derives it; nothing passes it by hand. `attended` is true for `user` and for a manual routine run. A manual run is still `kind: "routine"`, so routine bans apply to it. The `bot` and `agent` kinds are hops and carry `hops` and `origin`. `origin` is the `Origin` (`user`, `routine` or `system`) where the chain began, and `world.rootOf` reads it from any initiator. `hops` counts bot-to-bot hops along the whole chain. A bot message or creation carries `world.hopsAfter(turn)`, which is one more than `world.hopsOf(turn)`. An agent report carries the agent turn's `hopsOf` unchanged, so an agent hop neither adds a hop nor resets the count. The lineage is flattened, so a persisted initiator never nests however long the chain grows.
- **Queued input.** `prompts.inputOf(envelope, userName)` gives the `SessionInput` (`kind`, `text`, `initiator`, `settles`) that `Session.push` queues and `Pending` keeps. `kind` is `continuation` only for a decision envelope (`kindOf`): it goes right behind the turn in flight, Stop never drops it, and when its turn is sent on an open query the session calls `spec.continuing`, which the hub and agents wire to `gate.beginTurn`. `settles` is the routine run, set only for a routine's own fire. The hub settles a run from `Pending.settles` and never from the initiator, so an approval continuation that carries a routine's initiator never settles the run again. The scheduler's boot sweep and overlap check read `settles` too.
- **Turn output (hub).** The hub reads only the turn in flight (`onMessage`'s `turn` argument), so envelopes Stop drops while it runs never reset it, and output with no turn posts as plain bubbles. A routine's scheduled fire (`settles` set, not manual) holds its bubbles until its end. `turn.quiet && !turn.asked` drops them, settles the run `quiet` and pushes nothing. Otherwise its bubbles post as they arrive or at the end. The turn's first bubble tries a `message` push after `post`, so the push throttle sees the message; when none went out, its last bubble tries one at the end, and when the push that did go out is 20 s or more old, the last bubble pushes with reason `result`. Bubbles before an `ask`, before a permission card the bot's own turn opens, and before a note the session posts mid-turn (the breaker's, a stall, a sandbox failure) go out at once, and a turn that opened its own permission card is never quiet. A `stopped` end notes "Stopped by <user>" only when `by` is `user`; a breaker stop settles a routine run `skipped` with `BREAKER_NOTE`. A turn that `usedBudget` notes that the bot used today's budget, and its routine run settles `skipped`. Bot status reads `session.unavailable`, then `session.working`, then `session.parkedFor`, and `awaiting_approval` counts every open permission or trust card with `actor.botId` equal to the bot, agents' cards included.
- **Gate.** The order is floors, initiator bans, limits, Never, grant, Always, the table, then pass. The routine bans test `world.isRoutineChain(initiator)`, and the hop cap tests `world.hopsOf(initiator) >= 2`, so both hold through agent hops. A Bash call's `allowed_domains` is a part of its own, matched by the `net.hosts` row (attended pass, unattended ask, no Always) and folded into its fingerprint. `forgetBot(botId)` drops the bot's open cards, the grants and agent trust answers of the bot and its agents, and its daily counts; `delete_bot` calls it before `persist("now")`. `ask` posts a permission card and returns SDK `deny` with the held reason; SDK `ask` and `defer` are never returned. A gate transition that opens a card, consumes a grant or adds a rule calls `persist("now")` before the audit append and before the hook returns. A grant is created at the 24 h ceiling and shortened to 10 minutes by `beginTurn`. A repeated `tool_use_id` gets the recorded verdict. The hook body is synchronous and stays inside `failClosed`, because a throwing hook fails open. `toCall` keeps `subagent` (`agent_id`, `agent_type`) and `mcpServer`. Policy passes the SDK's own `Agent` and `SubagentHandback` calls. The gate reports each hold or deny through `GateDeps.denied`, and it denies every call while `turnOf(actor).stopping` is true.
- **Repo trust.** A mac agent's options carry `projectConfigRoot: deps.configRoot(agentId)` (`homes.agentConfig`, an empty 0700 folder in the bridge home) until `world.repoTrust(gate, cwd, agentId)` is true. `agents.start` calls `gate.trustCard` when `projectConfigOf(cwd)` finds config; the gate posts one card per repo and skips a repo already answered. The answer table: once → this agent, always → every agent (and it replaces the repo's earlier answers), deny → not this agent, never → no agent; an expired card decides nothing and tells nobody. A trusting answer calls `GateDeps.trusted(root)` → `agents.trusted(root)` → `session.reopen()` for each live agent in the repo.
- **Session.** `Lifecycle` holds `idle`, `working`, `stopping`, `backoff` and `parked`, and stores every deadline. The lifecycle is `parked` exactly while the queue head is held, for the account's usage limit as well as the daily cap. `world.holdOf(state)` reads the hold from it, and the hub shows `parked` only for a held head with no turn running. While stopping, the interrupt's `error_during_execution` result maps to `TurnEnd` `stopped`, which is never a failure and is never retried. Each envelope that leaves the queue gets exactly one `TurnEnd`. Stop removes queued unattended envelopes as `dropped`, each with a notice. The third denial in one turn moves the session to `stopping` and calls `spec.note`. Notices go on top of the next envelope through `withNotices`. A query that cannot open (`unstarted`) requeues the head without using an attempt and backs off 30 s, 1, 2, then 5 minutes; `unavailable` is true meanwhile. A failed tool result naming `sandboxFailure` notes once per query and closes the query at the turn's end; it is no denial. A result or exit naming it before any output is `unstarted`. A query closes after `IDLE_MS` (15 minutes) with no turn and no message; `onDormant` lets the owner forget the session. An unattended turn gets a query of its own whose `maxBudgetUsd` is at most `ledger.dailyLeft`; an attended turn never runs on such a query.
- **Ledger.** The cost baseline is the session's last row. `add` takes `fresh?: boolean`, true when the query started without a resume id. A session with no row charges its whole cumulative when `fresh`, because the SDK's running total began at 0. Otherwise a session with no row (one resumed from before the ledger) adopts the first result and charges 0. The daily cap holds unattended turns only. Attended turns run, and `capReached` tells the session to note it.
- **Scheduler and clock.** The hub's `changed(bot, "now")` calls `persist("now")` before it broadcasts, and the scheduler delivers a fire only after that returns, so a fire is at most once. `SchedulerDeps.parked(bot, attended)` is true when no turn of that attendance can start: the account's usage limit, or a `usage_limit` hold on the bot's session, holds every turn; for unattended work only, any hold or a reached daily cap does too. A hold whose `until` has passed does not count: the scheduler ticks before the sessions clear it. `update_bot` with `dailyCapUsd` calls `recheck()` on the bot's session and its mac agents' sessions. `nextRunAt` advances before a fire. An overdue routine fires once inside the grace window, or else records `skipped`. `settle` is called exactly once per fire, for the fire's own turn end. `upsertRoutine` clears `nextRunAt` when the trigger or `enabled` changes, and re-enabling also clears `failStreak`. The clock ticks every `Tickable` at boot, at the earliest `nextDeadline`, and at least every 60 s. The hub's tickers are the scheduler, the gate, push, and an aggregate of all live sessions. A ticker that throws is logged and the rest still run (`hub.tickEach`). The hub calls `clock.poke()` from its `changed()`, which `say`, `note`, every bot session's `onChange` and every agent change reach. A module that moves a deadline must reach one of them, or the clock sleeps past it until the 60 s cap.
- **Transport.** `serve.ts` answers `devices`, `revoke_device` and `pair_code` before `hub.handle`, which replies to them with an error. It passes `hub.hello(stream.position(resumed))` (the position is required) and publishes `stream.append(message)`. A socket is live while it was heard from in the last 45 s (the app pings every 20 s; the server pings a socket silent for 44 s), and `push` sends only while none is.
- **Protocol 2 sockets.** A socket that did not connect with `?protocol=3` subscribes to its own topic and gets every frame through `forProtocol2`: a permission card becomes a question card with the options `Allow once` and `Deny` (answered `once`/`always` → 0, `deny`/`never` → 1, `expired` kept), with the same `seq`. It is never offered a resume, because the ring holds protocol 3 frames. The hub reads an `answer` on a permission card through `cardReply` as `decide` once (option 0) or deny (option 1), refuses any other option, and reads `dismiss` on one as deny. Such a socket and the legacy device may revoke only themselves and decide only once or deny. The shared token is refused from `LEGACY_SUNSET` (2027-01-01); a legacy socket open at that moment stays until it reconnects.
- **Agents.** A mac agent's query opens with `maxBudgetUsd: budgetLeft(agent)`, the agent's lifetime budget left, and a query opened for an unattended turn gets at most `dailyLeft` too (the session lowers it). The SDK counts spend from the query's open across every turn it serves, which matches a lifetime budget. Options carry `sandbox: sandboxFor(actor, scope, env, gitDirsOf(cwd))`, `env: { ...process.env, ...AGENT_GIT_ENV }` (the SDK replaces the environment), `settings: NO_AUTO_MEMORY` and, until the repo is trusted, `projectConfigRoot`. Bot queries carry `sandbox: sandboxFor(actor, scope, env)` and `settings: NO_AUTO_MEMORY`.
- **Grants.** `Grant.appliesTo` is `attended` or `unattended`, from the held call's initiator, and only a turn of that attendance may use the grant. It is persisted, so the binding survives a restart. It is not `attended | all` like `StandingRule.appliesTo`: a user's turn must not consume the grant a routine's continuation needs.

## Wire: protocol 3

Protocol 3 adds to protocol 2 and changes the meaning of no existing field.

- `hello.protocol`, plus `epoch`, `seq` and `resumed`. Broadcast frames carry `seq` (`Broadcast`).
- Message kind `permission` with `from`, `tool`, `label`, `detail`, `always`, `answer` (`once | always | deny | never | expired | null`) and `expiresAt`. A trust card is one of these with tool `Claude Code settings`. Questions gain answer `"expired"` and `expiresAt` (`null` for cards from before protocol 3).
- `Bot.status` gains `awaiting_approval`, `parked` and `unavailable`, and `Agent.status` gains the same three. `Bot.dailyCapUsd`, settable through `update_bot`.
- `Routine` keeps `schedule` and `describe`, and gains `trigger`, `nextRunAt` and `runs` (`RoutineRun` with `status`, `late`, `manual` and `note`). A `Bot` frame carries each routine's newest 5 runs (`RUNS_ON_BOT`), because every broadcast repeats it. `details` gains `routines`, each with every kept run (at most 20). `lastRunAt` is derived from the full history in both.
- Client messages: `decide`, `stop`, `stop_agent`, `run_routine`, `devices`, `revoke_device` and `pair_code`. Server messages: `devices` and `pair_code`. HTTP: `PairRequest` and `PairResponse`.

`fixtures/protocol.json` holds 22 server and 20 client fixtures. `ios/ClaudioBot/Model/Protocol.swift` decodes every server fixture and encodes every client fixture to equal JSON, and the iOS tests read the list from the file, so a new fixture is covered without touching them. An app that does not know a kind, status or type decodes it as `.unknown`, and `"expired"` decodes as a closed card.
