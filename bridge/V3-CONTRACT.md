# Bridge v3 contract

This file maps the v3 bridge: each module's interface, the state it writes, and the rules the modules build on. The doc comments in each module carry the full invariants; this page is the index. A change to an interface listed here updates this page in the same commit.

## State: `state.json` version 3

`world.ts` declares every persisted shape. A slice typed `Owned<T>` is a readonly field holding deeply readonly data, so only its writer can change it. The writer calls `world.own()` and mutates in place.

| Slice | Type in `world.ts` | Only writer | Notes |
|---|---|---|---|
| `BotRecord` profile, `dailyCapUsd`, `muted` | `BotRecord` | `hub.ts` | `update_bot`, `update_self`; `push.ts` reads `muted`. `update_self` with `job` rewrites the `## Job` section of the bot's `CLAUDE.md`, and only in a turn whose initiator is `user` |
| `BotRecord.connectorsOff` | `string[]` | `connectors.ts` | MCP servers turned off for the bot and its agents; the gate denies calls to them |
| `BotRecord.messages`, `.unread` | `Message[]` | `hub.ts` (`say` → `post`) | the gate and scheduler call the hub's `say` and `note`; past 1,100 messages the oldest move to `<bot home>/.history/bot.jsonl` (an agent's to `.history/<agentId>.jsonl`), open cards stay |
| `BotRecord.session`, `AgentRecord.session` | `SessionState` (`Pending`, `ActiveTurn`, `Lifecycle`, `Notice`) | `session.ts` | resume id, durable inbox, lifecycle with deadlines, notices, and `sent` (digests of the standing brief and the memory context the session last delivered). `Pending.kind` is `continuation` for a decision envelope, `envelope` otherwise; `Pending.settles` names the routine run a turn end settles |
| `World.account` | `AccountState` | `session.ts` | account-wide usage-limit park |
| `World.groups` | `GroupRecord` (a `ChatRecord` with `members`) | `hub.ts` | `create_group`, `update_bot`, `delete_bot`, posts by `sayInGroup`; `state.json` key `groups`, absent before groups. No session, routines, rules or connectors, so nothing that walks `World.bots` reaches one. `Pending.group` names the group a member's turn answers in; past 1,100 messages a group's oldest move to `groups/<groupId>.jsonl` |
| `BotRecord.routines` | `RoutineRecord[]` | `scheduler.ts` | `nextRunAt`, newest 20 runs, `failStreak`; `Trigger` is `cron` or `webhook` (with `tokenHash`, no `nextRunAt`) |
| `BotRecord.rules` | `StandingRule[]` | `gate.ts` | Always/Never, keyed by `Signature`, allow rules carry `appliesTo` |
| `World.gate` | `GateState` (`OpenCard`, `Grant`, `DailyCount`, `RepoTrust`) | `gate.ts` | card deadlines (question, permission and trust cards), permission match keys, one-shot grants with the attendance of the card that made them, daily tool counts, trust answers per repo, and `aliveAt`, the last minute the bridge ran with a card open |
| `World.devices` | `DeviceRecord[]` | `devices.ts` | token hashes only; `legacy` marks the imported protocol-2 token |
| `World.push` | `PushState` | `push.ts` | `${messageId}|${reason}` keys (reason `card`, `reminder`, `message` or `result`), recorded before sending |
| `AgentRecord.agent`, `.cloudSession`, `.startedBy`, `.repo`, `.base` | `Agent`, `string \| null`, `Initiator`, `string`, `string \| null` | `agents.ts` | cloud agents are neither gated nor metered; `startedBy` is the bot turn's initiator at `start_agent`; `agent.evidence` and `agent.worktree` live on the wire record; `repo` is the project's realpath read at start, which repo trust, project config and worktree removal key on; `base` is the commit a worktree started from |

`store.ts` owns the file. `loadWorld` fails closed. `checkStateFile(parsed)` is the pure check it runs, and the doctor runs the same one without loading: every bot and agent record (v3) or every v2 record against the fields the bridge reads. A malformed record, an unknown version, unreadable JSON or a failed upgrade throws `StateFileError` without writing anything. A v3 file written before `Pending.kind` or `GateState.repos` is read with a continuation recognised by its `c_` id prefix and no trust answers. Fields added after version 3 shipped are optional in the check and filled in `fromV3`: `muted` false, `connectorsOff` empty, agent `evidence` and `worktree` null. `agents.ts` keys an agent record without `repo` on its `cwd`. A trigger of an unknown kind is refused. A v2 file is upgraded in memory first, then its exact bytes are copied to `state.v2.json.bak`, then v3 is written in place. A v1 file is backed up to `state.v1.json.bak` and treated as a first run. A backup is never overwritten. When the name holds other bytes, the copy goes to the next free `.1`, `.2` suffix, and bytes already backed up are not copied again.

`flushNow(world, home)` and `saver.schedule("now")` write synchronously. They write the whole body to a temp file with a unique name, `fsync` it, check its size, rename it over `state.json` with mode 0600, then `fsync` the directory. The guarantee is against a crash of this process. On macOS `fsync` does not flush the drive cache (that needs `F_FULLFSYNC`), so a power loss can still lose the newest write. `saver.schedule()` debounces by 250 ms. A failed debounced write is logged, stays pending and retries with a doubling delay capped at 30 s. `saver.schedule("now")` and `saver.flush()` throw when the write fails, with the retry still armed. `Persist = (urgency?: "now") => void` is the type every module receives, and a module whose `persist("now")` throws must not perform the effect the write was meant to precede.

README, upgrading: "Once the new bridge has started, do not run an older bridge against the same home. It does not know state version 3, treats the file as a first run and overwrites it. To go back, stop the new bridge and copy `state.v2.json.bak` over `state.json` first; anything changed since the upgrade is lost."

## Rules each module builds on

- **Initiator.** `prompts.initiatorOf(envelope)` derives it; nothing passes it by hand. `attended` is true for `user` and for a manual routine run. A manual run is still `kind: "routine"`, so routine bans apply to it. The `bot` and `agent` kinds are hops and carry `hops` and `origin`. `origin` is the `Origin` (`user`, `routine` or `system`) where the chain began, and `world.rootOf` reads it from any initiator. `hops` counts bot-to-bot hops along the whole chain. A bot message or creation carries `world.hopsAfter(turn)`, which is one more than `world.hopsOf(turn)`. An agent report carries the agent turn's `hopsOf` unchanged, so an agent hop neither adds a hop nor resets the count. The lineage is flattened, so a persisted initiator never nests however long the chain grows.
- **Queued input.** `prompts.inputOf(envelope, userName)` gives the `SessionInput` (`kind`, `text`, `initiator`, `settles`) that `Session.push` queues and `Pending` keeps. `kind` is `continuation` only for a decision envelope (`kindOf`): it goes right behind the turn in flight, Stop never drops it, and when its turn is sent on an open query the session calls `spec.continuing`, which the hub and agents wire to `gate.beginTurn`. `settles` is the routine run, set only for a routine's own fire. The hub settles a run from `Pending.settles` and never from the initiator, so an approval continuation that carries a routine's initiator never settles the run again. The scheduler's boot sweep and overlap check read `settles` too.
- **Turn output (hub).** The hub reads only the turn in flight (`onMessage`'s `turn` argument), so envelopes Stop drops while it runs never reset it, and output with no turn posts as plain bubbles. A routine's scheduled fire (`settles` set, not manual) holds its bubbles until its end. `turn.quiet && !turn.asked` drops them, settles the run `quiet` and pushes nothing. Otherwise its bubbles post as they arrive or at the end. The turn's first bubble tries a `message` push after `post`, so the push throttle sees the message; when none went out, its last bubble tries one at the end, and when the push that did go out is 20 s or more old, the last bubble pushes with reason `result`. Bubbles before an `ask`, before a permission card the bot's own turn opens, and before a note the session posts mid-turn (the breaker's, a stall, a sandbox failure) go out at once, and a turn that opened its own permission card is never quiet. A `stopped` end notes "Stopped by <user>" only when `by` is `user`; a breaker stop settles a routine run `skipped` with `BREAKER_NOTE`. A turn that `usedBudget` notes that the bot used today's budget, and its routine run settles `skipped`. Bot status reads `session.unavailable`, then `session.working`, then `session.parkedFor`, and `awaiting_approval` counts every open permission or trust card with `actor.botId` equal to the bot, agents' cards included.
- **Gate.** The order is floors, initiator bans, refusals, limits, Never, grant, Always, the table, then pass. Refusals deny a claudio tool the bridge does not serve (`claudio.unknown`) and a call to a connector in the bot's `connectorsOff` (`connector.off`), matched by the hook's `mcp_server` name or by Claude Code's `mcp__<server>__` tool prefix. While any connector is off, a connector call that names no server is denied too. Every claudio tool has an entry in policy's `CLAUDIO` record, keyed on `ClaudioTool`, so a tool cannot ship unclassified: `remember` (`claudio.remember`, no Always) and `save_skill` (`claudio.save_skill`) pass attended and ask unattended, like `create_bot`, `start_agent` and the routine tools. The `memory.user` row asks before any direct write to USER.md in every turn, with no Always, because a direct write would skip remember's proposal step and reach every bot at once. Writes to the bot's own CLAUDE.md and `.claude/skills` stay `self.escalate` in every turn, because memory and skills go through their tools. The routine bans test `world.isRoutineChain(initiator)`, and the hop cap tests `world.hopsOf(initiator) >= 2`, so both hold through agent hops. A Bash call's `allowed_domains` is a part of its own, matched by the `net.hosts` row (attended pass, unattended ask, no Always) and folded into its fingerprint. `forgetBot(botId)` drops the bot's open cards, the grants and agent trust answers of the bot and its agents, and its daily counts; `delete_bot` calls it before `persist("now")`. `ask` posts a permission card and returns SDK `deny` with the held reason; SDK `ask` and `defer` are never returned. A gate transition that opens a card, consumes a grant or adds a rule calls `persist("now")` before the audit append and before the hook returns. A grant is created at the 24 h ceiling and shortened to 10 minutes by `beginTurn`. A repeated `tool_use_id` gets the recorded verdict. The hook body is synchronous and stays inside `failClosed`, because a throwing hook fails open. `toCall` keeps `subagent` (`agent_id`, `agent_type`) and `mcpServer`. Policy passes the SDK's own `Agent` and `SubagentHandback` calls. The gate reports each hold or deny through `GateDeps.denied`, and it denies every call while `turnOf(actor).stopping` is true. The `floor.localnet` floor denies a WebFetch, and any connector call with a string `url` input, whose host is loopback, private, link-local, CGNAT or unspecified, an IPv6 address that carries such an IPv4 (`::ffff:`, `64:ff9b::/96`, `2002::/16`), a dotless name, or a name under `.localhost`, `.local`, `.lan`, `.internal`, `.home.arpa` or `.ts.net`, after trailing dots are stripped. It is a floor, so it holds in attended turns too, and a localhost dev server is out of reach of WebFetch. A public name that resolves to a private address is not caught. `connector.act` passes an unattended connector call only when its name has a read verb (`get`, `list`, `read`, `search`, `find`, `describe`, `view`, `count`) and no write verb; `fetch` is neither, so a fetch connector asks unattended. The `self.escalate` row (ask in every turn, no Always) covers the shell rc files, `.bash_aliases`, `.vimrc`, `.exrc`, `.tmux.conf`, `.inputrc`, `~/.config/nvim` and `~/.vim`.
- **Shell commands.** A Bash command over 32 KB is held as `bash.toolong` before it is parsed. A call that would resolve more than 4,096 distinct paths (`REALPATH_BUDGET`) is denied when its raw text spells a floor root and is otherwise held as `bash.toolong`. An interpreter (`python`, `node`, `bun`, `deno`, `ruby`, `perl`, `php`, `lua`, `osascript`, `R`, `swift`, `awk`, `sqlite3`, `vim`, `vi`, `nvim`, `ex`, `emacs` and the others in `INTERPRETER`) or a launcher (`uv`, `uvx`, `poetry`, `pipenv`, `pdm`, `rye`, `hatch`, `conda`, `mamba`, `pixi`) may write any file its code names. `interpreterWrites` reads the names `CLAUDE.md`, `USER.md`, `.mcp.json` and `.claude/` only from that command's own words and from heredocs opened on its line, never from other commands on the line, and turns each into a write touch. A `USER.md` spelled anywhere in that code is also a write to the user's `USER.md`, which `memory.user` asks for. More than 64 distinct names in one interpreter part is held as `bash.toolong`. `git.push.remote` asks in every turn, with no Always, for a push whose remote is a URL, an `ext::` remote, a scp-style `host:path` or a local path, a remote added or re-pointed earlier on the same line, a push on a line that sets a `GIT_CONFIG_*` variable, a git `-c` (attached or separate) or `--config-env` that sets `remote.*.url`, `remote.*.pushurl`, `url.*.insteadOf` or `include.path` and `includeIf.*.path`, or a push with `--repo`, `--receive-pack` or `--exec`. Re-pointing a remote in a call of its own asks the same way: `git remote add`, `git remote set-url`, and `git config` with a value for any of those keys.
- **Cards.** `detailOf` shows the exact command, `Write <path> (N lines)`, or an MCP tool with compact JSON, clipped with its length and a hash. Nothing in it is masked, because the approver must see what runs. Control and format characters, U+2028 and U+2029, the no-break space and the Hangul fillers show as `<U+XXXX>`. The detail is stored as shown, in the permission message and the open card in `state.json` and later in `.history/`. The audit row keeps only `redact(call.input)`. A card that is open records `GateState.aliveAt` each minute, and `gate.resume(now)` at boot hands open cards back the time the bridge was down through `wake`.
- **Repo trust.** A mac agent's options carry `projectConfigRoot: deps.configRoot(agentId)` (`homes.agentConfig`, an empty 0700 folder in the bridge home) until `world.repoTrust(gate, cwd, agentId)` is true. `agents.start` calls `gate.trustCard` when `projectConfigOf(cwd)` finds config; the gate posts one card per repo and skips a repo already answered. The answer table: once → this agent, always → every agent (and it replaces the repo's earlier answers), deny → not this agent, never → no agent; an expired card decides nothing and tells nobody. A trusting answer calls `GateDeps.trusted(root)` → `agents.trusted(root)` → `session.reopen()` for each live agent in the repo.
- **Session.** `Lifecycle` holds `idle`, `working`, `stopping`, `backoff` and `parked`, and stores every deadline. The lifecycle is `parked` exactly while the queue head is held, for the account's usage limit as well as the daily cap. `world.holdOf(state)` reads the hold from it, and the hub shows `parked` only for a held head with no turn running. While stopping, the interrupt's `error_during_execution` result maps to `TurnEnd` `stopped`, which is never a failure and is never retried. Each envelope that leaves the queue gets exactly one `TurnEnd`. Stop removes queued unattended envelopes as `dropped`, each with a notice. The third denial in one turn moves the session to `stopping` and calls `spec.note`. Notices go on top of the next envelope through `withNotices`. A query that cannot open (`unstarted`) requeues the head without using an attempt and backs off 30 s, 1, 2, then 5 minutes; `unavailable` is true meanwhile. A failed tool result naming `sandboxFailure` notes once per query and closes the query at the turn's end; it is no denial. A result or exit naming it before any output is `unstarted`. A query closes after `IDLE_MS` (15 minutes) with no turn and no message; `onDormant` lets the owner forget the session. An unattended turn gets a query of its own whose `maxBudgetUsd` is at most `ledger.dailyLeft`; an attended turn never runs on such a query. Before a turn is sent, `spec.brief` (the standing brief: persona, name and the `## Job` section) and `spec.context` go on top of its text when their digest differs from `SessionState.sent`. A new session records the brief without sending it, because its system prompt is current. `sent` is updated only once the model answers the turn, so a turn that never ran carries them again. When a resumed query's first turn fails before any output with "No conversation found with session ID: <the resumed id>", the session clears its id, requeues the turn without using an attempt, notes it in the chat, and tells the new session its history is gone. Any other failure, or a later turn on that query, is handled as usual.
- **Ledger.** The cost baseline is the session's last row. `add` takes `fresh?: boolean`, true when the query started without a resume id. A session with no row charges its whole cumulative when `fresh`, because the SDK's running total began at 0. Otherwise a session with no row (one resumed from before the ledger) adopts the first result and charges 0. The daily cap holds unattended turns only. Attended turns run, and `capReached` tells the session to note it.
- **Scheduler and clock.** The hub's `changed(bot, "now")` calls `persist("now")` before it broadcasts, and the scheduler delivers a fire only after that returns, so a fire is at most once. `SchedulerDeps.parked(bot, attended)` is true when no turn of that attendance can start: the account's usage limit, or a `usage_limit` hold on the bot's session, holds every turn; for unattended work only, any hold or a reached daily cap does too. A hold whose `until` has passed does not count: the scheduler ticks before the sessions clear it. `update_bot` with `dailyCapUsd` calls `recheck()` on the bot's session and its mac agents' sessions. `nextRunAt` advances before a fire. An overdue routine fires once inside the grace window, or else records `skipped`. `settle` is called exactly once per fire, for the fire's own turn end. `upsertRoutine` clears `nextRunAt` when the trigger or `enabled` changes, and re-enabling also clears `failStreak`. The clock ticks every `Tickable` at boot, at the earliest `nextDeadline`, and at least every 60 s. The hub's tickers are the scheduler, the gate, push, an aggregate of all live sessions, and a midnight ticker that resends every `bot` frame when the local day changes, so `spentTodayUsd` resets on the phone. A ticker that throws is logged and the rest still run (`hub.tickEach`). The hub calls `clock.poke()` from its `changed()`, which `say`, `note`, every bot session's `onChange` and every agent change reach. A module that moves a deadline must reach one of them, or the clock sleeps past it until the 60 s cap.
- **Lock.** `lockHome` writes `<pid>\n<start>\n`, the start being `ps -o lstart=` in UTC. A lock is stale when its pid is dead or that process started at another time. A lock holding a start in the Mac's time zone, as an older bridge wrote it, still matches. A live holder whose start `ps` cannot read is busy. Only a lock with no recorded start is also stale when it was written before the Mac booted.
- **Transport.** `serve.ts` answers `devices`, `revoke_device` and `pair_code` before `hub.handle`, which replies to them with an error. It passes `hub.hello(stream.position(resumed))` (the position is required) and publishes `stream.append(message)`. A socket is live while it was heard from in the last 45 s (the app pings every 20 s; the server pings a socket silent for 44 s), and `push` sends only while none is. `GET /health` answers `{"ok":true}`; with `?device=<id>&nonce=<32 to 128 hex digits>` for a paired device that is not legacy, it adds `proof`, the hex HMAC-SHA256 of the nonce keyed by the raw bytes of the sha256 of that device's token (`Devices.prove`). The app checks it before it sends the token to a new address. `pairLink` repeats `url=` for every address `bridgeUrls` gives, best first (the tailnet name, the Bonjour `.local` name, then each LAN IPv4). `readNames` finds `tailscale` on `PATH`, then in `/opt/homebrew/bin` and `/usr/local/bin`, then in Tailscale.app, and `main.ts` kills a helper command (`scutil`, `tailscale status`, `id -F`) after 2 s.
- **Protocol 2 sockets.** A socket that did not connect with `?protocol=3` subscribes to its own topic and gets every frame through `forProtocol2`: a permission card becomes a question card with the options `Allow once` and `Deny` (answered `once`/`always` → 0, `deny`/`never` → 1, `expired` kept), with the same `seq`. It is never offered a resume, because the ring holds protocol 3 frames. The hub reads an `answer` on a permission card through `cardReply` as `decide` once (option 0) or deny (option 1), refuses any other option, and reads `dismiss` on one as deny. Such a socket and the legacy device may revoke only themselves and decide only once or deny. The shared token is refused from `LEGACY_SUNSET` (2027-01-01); a legacy socket open at that moment stays until it reconnects.
- **Sandbox.** A bot's Bash writes only `BOT_WRITABLE` (`library/`, `inbox/`, `work/`) in its home, plus the sandbox's own `TMPDIR`, and is denied `**/CLAUDE.md`, `**/CLAUDE.local.md`, `**/.claude` and `**/.mcp.json` at any depth under its home, and `USER.md`; Claude Code turns these globs into Seatbelt regexes. `homes.create` makes the three folders, and the bot's `options()` calls `homes.ensureFolders` as each query opens, so a bot made before `work/` existed gets it. A mac agent's Bash writes its cwd but not the cwd's `.claude`, `.mcp.json` or `CLAUDE.local.md`; `CLAUDE.md` stays writable, and a Write or Edit of it still asks. `PRIVATE` keeps `.terraform.d/credentials.tfrc.json` and `.m2/settings-security.xml` but not `.terraformrc` or `.m2/settings.xml`, which builds read.
- **Agents.** A mac agent's query opens with `maxBudgetUsd: budgetLeft(agent)`, the agent's lifetime budget left, or with no `maxBudgetUsd` when it has no budget, and a query opened for an unattended turn gets at most `dailyLeft` too (the session lowers it). The SDK counts spend from the query's open across every turn it serves, which matches a lifetime budget. Options carry `sandbox: sandboxFor(actor, scope, env, gitDirsOf(cwd))`, `env: { ...process.env, ...AGENT_GIT_ENV }` (the SDK replaces the environment), `settings` (`NO_AUTO_MEMORY` plus the bot's `connectorSettings`) and, until the repo is trusted, `projectConfigRoot`; a trusted worktree's points at its main checkout. Bot queries carry `sandbox: sandboxFor(actor, scope, env)`, the same `settings`, and the persona alone in `systemPrompt.append`.
- **Agent turn ends.** After a `done` turn end the agent's report waits for `readEvidence(cwd, text, now, base)`; reports queue per agent, so a later stop or crash never overtakes one still reading git. The evidence goes on `Agent.evidence`, and `reportText` puts the bridge's `[Git, read by the bridge after this turn: …]` line (or `[Git: not readable]`) above the agent's words; an agent line that opens with `[Git` is marked as the agent's. A turn that `usedBudget` reports `capped` ("Paused at today's spending cap; it resumes when you message it tomorrow or raise the cap.") while `ledger.budgetLeft` is above 0 or null (no budget), and `failed` when the lifetime budget ran out.
- **Hardened git.** `hardenedGit(cwd)` is the one way the bridge runs git in a repo: `core.fsmonitor` false, `core.hooksPath` `/dev/null`, `protocol.file.allow` never, `core.pager` cat, every filter driver the config names blanked and made optional, all passed as `GIT_CONFIG_KEY_n`/`VALUE_n` with `GIT_CONFIG_NOSYSTEM`, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0` and no inherited `GIT_*` variable, killed after 10 s. Diffs add `--no-ext-diff --no-textconv`, refs and paths go after `--end-of-options`, and the default branch reaches git only as a SHA.
- **Worktrees.** `start_agent`'s `isolate` is `none`, `worktree` or `auto` (default). `prepareWorkspace` makes a worktree at `worktreesRoot()/<project>/<agentId>` (`CLAUDIOBOT_WORKTREES`, default `~/.claudiobot-worktrees`) on branch `claudio/<first 8 of the id>` from the default branch's local commit, else origin's. `auto` makes one when the checkout has uncommitted work or another live mac agent works in the folder, and stays in the folder, with a note, when there is no `main` or `master`. A trusted worktree loads project config from its main checkout. `Agents.removeWorktree` (the phone's `remove_worktree`) refuses while the agent works, has queued input or has an open card, and `worktree.removeWorktree` refuses uncommitted or untracked work and ignored files outside `REGENERABLE` (`node_modules`, `.build`, `dist`, `build`, `DerivedData`). It runs `git worktree remove` without `--force`, keeps the branch, and prunes when the folder is already gone. Nothing else removes a worktree. An agent whose worktree was removed cannot continue.
- **Memory.** USER.md's `## Facts` and each bot's CLAUDE.md `## Notes` are files, not state. A fact line carries an HTML comment with its id, time, `proposed:<botId>` while unconfirmed, and its author. A hand-written line gets an id from its text and is tagged at the next write. `remember` about `user` appends a proposal; about `self` it appends a note. `context(botId)` holds the confirmed facts and this bot's own proposals, marked `(unconfirmed)`, fenced and labelled as data, at most `MEMORY_CONTEXT_MAX` (3 KB). The bot's session reads it before each turn and puts it on top of the turn's message when it differs from what that session last sent (a cleared list sends `notices.contextCleared`). A hand-written line counts as confirmed, because no bot writes `USER.md` unseen: the bot sandbox denies it and a Write or Edit of it is a card. It is not in the system prompt, because a resumed Claude Code session keeps the system prompt it started with. It re-checks every line, logs the ones it leaves out, and never throws. `confirm_fact` drops the proposer, and `set_fact` and `confirm_fact` drop proposals with the same text. Text is refused when empty, over 300 characters, once 50 facts or 50 notes are kept, with hidden characters or an HTML comment, or when it looks like a secret (`maskSecrets`, a password, PIN or SSN with its value, or 13 to 19 digits that pass the Luhn check). A bot's fact is also refused when it reads as an instruction to bots. Writes are atomic and refuse a symlink. A change broadcasts `memory` and reopens the proposer's query for a proposal and every bot's for a confirmed fact. When `ensureUserMd` fails at boot, the hub logs it and starts anyway; `remember` about the user fails until the file can be written.
- **Skills.** `save_skill` writes `bots/<id>/.claude/skills/<name>/SKILL.md`: frontmatter `name` and a JSON-quoted `description`, then the body. The file is 0600 in 0700 folders, written to a temp file and renamed, and a symlinked or non-plain folder or SKILL.md is never written through or replaced. Limits: name `^[a-z0-9]+(-[a-z0-9]+)*$` up to 64, a one-line description up to 200, a body up to 20 KB, well-formed text, no hidden characters or secrets, 30 skills. After a save or delete the bot's query reopens and every phone gets a `skills` frame. `delete_skill` answers nothing itself on success.
- **Connectors.** `connectorSettings(connectorsOff)` adds `deniedMcpServers` to the flag settings of every bot and agent query at open. `set` persists `connectorsOff` with `persist("now")`, calls `toggleMcpServer` on the live query, and reopens the bot's and its agents' queries. A server can be turned off only while the bot lists it, at most 64 per bot, never `claudio`. The phone gets each server's name, mapped status and `enabled`.
- **Activity.** `activityOf` reads only `tool_use` blocks. URLs are cut to their host and command-line options dropped with their values before `text.redact`, and a line is at most 80 characters. `observe` sends at most one line per actor per `ACTIVITY_THROTTLE_MS` (1.5 s), sends the trailing line when the window closes, and never sends the same text twice in a row. The line clears (`text: null`) at every turn end, a deferred one included, and on `delete_bot` before `bot_removed`. Tool use between turns sets no line. `HubDeps.signal` reaches `serve.signal`, which publishes to protocol 3 sockets only, with no `seq`. The line is never stored, replayed or pushed.
- **Sends.** A `send` whose `clientId` matches a user message already in the bot gets that message back as a `message` frame to the sender, and nothing is queued. The app keeps unechoed sends in memory, resends them after a hello to a bridge with the `mute` feature, and gives a send up once three sockets took its frame without an echo.
- **Webhooks.** `webhook.ts` listens on 127.0.0.1 only, on `HubDeps.webhookPort` (`CLAUDIOBOT_WEBHOOK_PORT`, default 7879, 0 for a free port; null, in tests, means no listener). `POST /hook/<routineId>` with `Authorization: Bearer whk_…` answers 403 for an `Origin` header or a `Host` other than `127.0.0.1:<port>` or `localhost:<port>`, 401 for a wrong or missing token, 413 past 16 KB, 429 within 60 s of the routine's last non-manual run (a last run in the future counts as elapsed), 409 when `Scheduler.hook` refuses (paused, still running, parked), 500 when the run could not be recorded or started, and 202 "Fired." The token is checked again after the body is read, and nothing awaits between that check and the fire. Only the token's sha256 is stored. `token()` mints a new one, which invalidates the old, and refuses when the listener could not bind. The payload reaches the bot fenced as data in the routine envelope. `upsertHook` keeps the token hash of a webhook routine it updates by name, and `routineView` gives a webhook routine `schedule` "" and `describe` "When its webhook is called".
- **Push.** `notify` sends no `message` or `result` push for a muted bot; cards and reminders still push. A card or reminder push for a card already open at start waits `START_GRACE_MS` (60 s) and then goes out only if no socket is live.
- **Deleting a bot.** `delete_bot` is refused while any of the bot's agents holds a worktree, unless the message carries `force: true`; the worktrees then stay on the Mac. Otherwise it closes the bot's session, stops its agents, calls `gate.forgetBot`, clears the activity lines, saves, moves the home to `trash/`, then removes each agent's `agent-config` folder, logging a failure.
- **Grants.** `Grant.appliesTo` is `attended` or `unattended`, from the held call's initiator, and only a turn of that attendance may use the grant. It is persisted, so the binding survives a restart. It is not `attended | all` like `StandingRule.appliesTo`: a user's turn must not consume the grant a routine's continuation needs.

## Wire: protocol 3 and its features

Protocol 3 adds to protocol 2 and changes the meaning of no existing field.

- `hello.protocol`, plus `epoch`, `seq` and `resumed`. Broadcast frames carry `seq` (`Broadcast`).
- Message kind `permission` with `from`, `tool`, `label`, `detail`, `always`, `answer` (`once | always | deny | never | expired | null`) and `expiresAt`. A trust card is one of these with tool `Claude Code settings`. Questions gain answer `"expired"` and `expiresAt` (`null` for cards from before protocol 3).
- `Bot.status` gains `awaiting_approval`, `parked` and `unavailable`, and `Agent.status` gains the same three. `Bot.dailyCapUsd`, settable through `update_bot`.
- `Routine` keeps `schedule` and `describe`, and gains `trigger`, `nextRunAt` and `runs` (`RoutineRun` with `status`, `late`, `manual` and `note`). A `Bot` frame carries each routine's newest 5 runs (`RUNS_ON_BOT`), because every broadcast repeats it. `details` gains `routines`, each with every kept run (at most 20). `lastRunAt` is derived from the full history in both.
- Client messages: `decide`, `stop`, `stop_agent`, `run_routine`, `devices`, `revoke_device` and `pair_code`. Server messages: `devices` and `pair_code`. HTTP: `PairRequest` and `PairResponse`.
- `hello.features` (`FEATURES`: `memory`, `activity`, `mute`, `worktrees`, `connectors`, `skills`, `webhooks`, `spend`) tells the app which screens this bridge backs. A `Bot` frame carries `BotSpend` (`spentTodayUsd`, `capUsd`, null when the bot has no cap), and `details` and `agent` frames carry `AgentView` (`spentUsd`, `budgetUsd`, null for cloud agents). `Bot.muted`, settable through `update_bot`. `send.clientId`, kept on the user's message. `Agent.evidence` (`AgentEvidence`: `branch`, `head`, `ahead`, `changed`, `insertions`, `deletions`, `dirty`, `pr`), `Agent.worktree` (`path`, `branch`) and agent status `capped`. Trigger `webhook`, with `schedule` "" and `describe` "When its webhook is called". `Fact` with `confirmed` and `proposerBotId` (the proposing bot, null once confirmed; the app matches a proposal to a chat by it and falls back to the name). `delete_bot` with optional `force`.
- Server frames: `activity` and `usage` (each a `Signal`: protocol 3 sockets only, no `seq`; a socket gets the latest `usage` right after its hello), `memory`, `connectors` (name, status and `enabled` per server, never configuration), `skills` and `webhook_token` (`url` and `token`, shown once). Client messages: `memory`, `set_fact` (`factId` null adds), `forget_fact`, `confirm_fact`, `connectors`, `set_connector`, `skills`, `delete_skill`, `webhook_token`, `remove_worktree` and `refresh_usage`. `PlanUsage` is `ok` (`plan`, `fetchedAt`, `stale`, `windows`: `UsageWindow` with `id`, `kind` `session | weekly | weekly_model`, `label`, `utilization` as a share of 1, `resetsAt`, `severity` `normal | warning | critical`) or `unavailable` (`reason` `api_key | third_party | logged_out | no_scope | failed`, `fetchedAt`). Feature `usage` is served only when the hub has a usage reader.

`fixtures/protocol.json` holds 38 server and 39 client fixtures. `ios/ClaudioBot/Model/Protocol.swift` decodes every server fixture and encodes every client fixture to equal JSON, and the iOS tests read the list from the file, so a new fixture is covered without touching them. An app that does not know a kind, status or type decodes it as `.unknown`, and `"expired"` decodes as a closed card.
